Workflow guide

How to use NexaFlow responsibly in this synthetic portfolio environment.

Agent workflow

  1. Open Outbound calling and choose the appropriate campaign.
  2. Claim one eligible work item before reviewing or recording an interaction.
  3. Use the call button to open the device dialler or configured calling application.
  4. Record a valid disposition, factual notes, and call duration.
  5. Schedule an explicit follow-up whenever the disposition requires one.

Safeguards

  • Keep the workbook synthetic; never upload real customer information.
  • Respect an opt-out immediately and record the reason only when necessary.
  • Do not use cohort views to make customer-level decisions.
  • Only administrators manage setup, campaigns, configuration, and readiness checks.
  • The call button does not connect to a calling vendor or capture calls.

Privacy and data boundaries

  • The workbook is seeded with fictional records only.
  • The browser calls only Apps Script services defined in this project.
  • The call action is a device tel: link; it does not transmit calls or recordings to a vendor.
  • Exports are generated locally from an authorized synthetic response.
  • Consent and opt-out operations create auditable workflow evidence.
  • Aggregate reports never make automated customer-level decisions.

Implementation decisions

Server authority
Apps Script validates role, authorization, and workflow state for each sensitive request.
Client role
The browser offers accessible controls, responsive navigation, and transparent feedback.
Concurrency
A claim plus an expiring server-side lock prevents conflicting interaction saves.
Reliability
Interaction submissions carry request IDs so a retried save is not duplicated.
Reviewability
Campaign, consent, verification, configuration, and governance actions have audit evidence.
